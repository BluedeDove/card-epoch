# 机制侧欠 UI 侧的接口清单（谁接什么，2026-10-17）

> 这份清单只写**机制已经把数据算出来了、但界面还没说给人听**的口子，不是 bug 单也不是红绿快照（那种东西隔天就骗人，见 AGENTS 协作习惯）。
> 规矩照旧：**结构进 `src/ui/panels.js` 的 spec，中文只进 `src/hud.js` 的 `H.TEXT`，数据只进 `src/ui/viewmodel.js`（唯一读 match 的地方）**。
> 机制线不会替 UI 线写文案；下面的「机制侧已备好」就是我这边的交付状态，缺的那格要 UI 侧来接。

## 1. 合架挂载（机制线的债，不是 UI 的）

- 三个文件还没进 `index.html` 的 script 序列：`src/lode-planter.js`、`src/reachability-gate.js`、`src/lode-system.js`。
- 后果要说白：**矿脉、连通闸、占矿得分目前只在 node 量表里成立，玩家页面里看不到矿**。这条由 `tools/play_probe.cjs` 的 L5 目标线红着盯，不是「应该绿了但没人看」。
- 顺序要求：planter 在 `world.js` 之后（它改写生成结果），`lode-system` 在 `battle.js` 之前（`Match` 构造时要 new 它）。三处都是 `if (G.X)` 守卫的，没挂就等于该阶段不存在，不会报错——**所以是静默失效，只能靠 L5 抓**。
- 谁来挂：合架归 UI 线（index.html 正在被他们重写），机制线等文件空档；期间我不碰 index.html，避免重演「整文件提交互相带走半成品」。

## 2. 顶栏：分数与三矿归属

- 机制侧已备好：每条矿的归属方、累计产出 `producedScore`、在场独占/争夺状态。kimi 已裁决**权威层总共只加两个布尔**（`contested`、可选 `graceActive`），都是「已经算出来了、只差暴露成公开字段」，不暴露计时秒数。
- 光柱按归属着色、顶栏三矿归属点、准星信息行、水晶亮度**全部是纯视图**，读 viewmodel；其中水晶亮度**不许让 LodeSystem 去写世界格**（那条纪律为的是同种子逐格可复现），叠加在渲染层做。
- 缺的那格：`vm` 里还没有矿归属字段，顶栏没有位置。

## 3. 结算面板：胜负原因与平局

- 机制侧已备好：`over.winReason` 取值 { score, time, overtime, overtime-tie, manual }，平局时 `winner = -1`、`name` 置空，**`over` 的五个键形状不变**（这条是 A1-b2 冻结的，为的就是面板不读新键也不出现 undefined）。
- 已知会落成错话的地方：面板现在按 `winner === 0` 判「你赢了」，所以平局会被显示成「你输了」。要新增的是「平局」这一支文案（进 `H.TEXT.result`），以及一行胜负原因的人话。
- 若将来启用 kimi 的「余晖产出」备胎：矿已判给对手、旧主还在计分，**HUD 必须如实显示「余晖」**，不许用一行文案糊过去——显示的归属与实际收益不一致，玩家只会当 bug。

## 4. 三个「发生了但没人说」的反馈

- **部分成交**：素材不够时结算器会按格截断（A0-a 的 `truncateQuote`），玩家现在完全看不出「我只建起了 5 格而不是 9 格」。机制侧有确切的建成格数与预算，缺界面说一句。
- **命数已退役**：胜负不再看 `killsToWin`，`lives` 降级成「夹 0 的记录字段」（复活流程与无敌帧都还在）。任何还写着「复活次数用完就输」的文案都已经是错的。
- **预测命中点**：瞄准时该不该显示弹着点，机制侧的 DDA 射线与 `aimOrigin` 是现成的，属于视图增强；**但判据一律走 `Rules.canPlay`，不要为了预览在视图里重算一套弹道**（「准星=命中格」那条不变量的同款坑）。
