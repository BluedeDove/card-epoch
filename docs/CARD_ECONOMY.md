# 卡牌纪元 · 卡牌来源与资源再生（定案 v1.1 · 2026-10-18）

> 地位：`docs/GAMEPLAY.md` 是玩法总纲（胜负、地图、占矿、三选一的原则）。
> 本文只回答两件还没被说死的事：**牌从哪来**（来源）与**资源怎么回到手里**（再生），
> 细到可以实现、可以被机检核对。数字与 GAMEPLAY §2.2/§2.3 一致；
> 与它不一致的地方在 §7 逐条列出理由，以本文为准。
> 代码现状（2026-10-18 实测）：魔力 cap 10 / +1.0 每秒整点 / 起始素材 5 / 以太晶采掉不回来 /
> 三选一与晶甲兽完全没接。本文就是把这几条推到定案值。

## 0. 一段人话

牌不是打怪掉的，也不是商店买的：**开局一套底牌，之后靠占矿从世界手里换牌**。
矿脉同时是三条再生链的源头——占着它给分、给素材、给一次三选一；它脚下那几根以太晶被采走 12 秒后长回来。
所以"占住矿"= 经济与牌的质量一起涨，这是本作**唯一**的成长线。

**三条纪律**：
1. 素材是"按格计价"的单一报价单（`R.priceTerrain` 是真源，部分成交在同一份报价上截断）。
2. 任何资源都**只经结算器/系统**写，UI 层不写、不猜（layer_check + owner_check 守着）。
3. 不给同一件事发两份钱：占矿的三份产出（分 / 素材 / 0.15 魔力）是三个不同用途，不是三次奖励（§6）。

## 2. 卡牌来源（只有四条）

### S1 开局牌库
- 默认 `starter` 12 张，**五类各 ≥1**：terrain / spell / sigil / summon / utility（`G.STARTER_DECK`）。
- 流派牌组（`fire/ice/rock/nature/void`）20 张同元素 + 4 张基础牌（strike/dig/place/draw1），
  生成用 `mulberry32(hash(流派) ^ seed)`，同种子完全一致。
- 本局内**不会**再得到基础牌以外的"补给"；牌只增不减（除出牌消耗）。

### S2 首占矿三选一（主要成长口）
- **触发**：某条矿第一次进入"某方独占"（LodeSystem 的 `owner` 由 -1 变成 side，且该矿未被该 side 触发过）。
- **数量**：每名玩家整局**上限 3 次**（来自占矿）；每次从池里取 **3 张不重复**，选 1 张。
- **入牌库**：选中的卡 **×2 直接进本局牌库**并立即重洗（`Match.grantCard`，MatchOps 第 16 个方法，已登记）。
- **面板**：复用 `H.openChoice`（GAMEPLAY §7.3 禁止第二套列表 UI）；开着时逻辑暂停、指针交还、滚轮让位。
- **跳过**：可以"先跳过"，次数不返还。
- **队列**：所有三选一（含 S3）进同一条 `pendingDrafts` 队列，一次只弹一个。

### S3 晶甲兽首杀三选一
- 每只晶甲兽**首次**被玩家击杀：击杀者 **+3 素材** + **1 次三选一**（池 = 通用池）。
- 上限：每名玩家整局 3 次（与 S2 分开计数，合计最多 6 次，即 12 张牌入牌库）。
- 晶甲兽不重生（首杀奖励只发生一次）。

### S4 弃牌堆重洗（回收，不产生新牌）
- 牌库抽空时把弃牌堆洗回牌库（`deck.js` 的 reshuffle）；这是"循环"不是"来源"，牌的总多重集守恒。

### 2.1 名义群系（解决 GAMEPLAY §6 的遗留问题）
三个基准 seed 的三矿落点全部落在翠绿林海（GAMEPLAY §6 实测），若按实际地形取池，
局内成长会退化成单一路线。定案采用 GAMEPLAY §6 的候选解 ①：

- **三矿的"名义群系"由 seed 派生**：`mulberry32(seed ^ 0xB10E)` 洗三个群系的排列（6 种），
  三矿**必定互不相同**（林海 / 黄沙 / 雪原各一条）。
- 与矿的实际地形无关；不改地形生成，不动 H1（同 seed 逐格一致仍成立）。
- 群系→元素池（每池 8 张，cost ≤ 5，选 3 张不重复）：

| 群系 | 元素 | 池（卡 id） |
|---|---|---|
| 林海 | nature + rock | raise, ramp, spikes, golem, dryad, bloom_field, entangle, bulwark |
| 黄沙 | fire + rock | bolt, bloom, firewall, ignite, supernova, obsidian_cage, fortress, shift |
| 雪原 | ice + void | shard, freeze, icewall, glacier, frost_nova, storm_hawk, void_lance, blink |
| 通用（兽首杀用） | neutral | draw1, overload, focus, anchor, push, kick, totem, snare_trap |

- 池按卡 id 固定顺序存放；取样用**专用随机流** `mulberry32(seed ^ 0xD4A7)`（不与其他系统共用序列，
  同 seed 同操作顺序可复现）——**不许**新增未播种随机源（H1 的命）。

## 3. 资源再生（五个循环）

### 3.1 魔力：时间驱动
```
manaCap = 8
regen(base) = 0.9 / 秒 + (本 tick 独占任一矿 ? 0.15 : 0)
manaAcc += dt * regen
while (manaAcc >= 1 && mana < manaCap) { manaAcc -= 1; mana++ }
若 mana >= manaCap: manaAcc = 0
```
- 起始 3；复活 `min(cap, 2)`；创造模式照旧 `infiniteMana`。
- 占矿加成由 LodeSystem 回答（`manaBonusOf(side)`），**不让 LodeSystem 直接写 p.mana**——
  写入仍归 battle.js，保持"一个字段一个家"。

### 3.2 素材：三条收入
| 来源 | 量 | 条件 |
|---|---|---|
| 占矿被动 | +1 / 6 秒 | 该矿由你独占（争抢不计） |
| 采晶 harvest | +1 / 格 | 瞄准到 CRYSTAL 并打出 harvest；同次 +3 魔力 |
| 晶甲兽首杀 | +3 | 首次击杀，每局最多 3 次 |
| 建造支出 | −1 / 格 | 建造类地形卡；**挖掘零成本**；付不起的部分不成交（部分成交） |

### 3.3 以太晶：12 秒原位再生
- 每矿 3 格晶体位置在生成期就写进 `world.lodes.list[i].crystals`（planter 的 `writeLode`）。
- 采掘（harvest 命中 CRYSTAL）时，`rules` 调 `match.onCrystalHarvested(x,y,z)`，
  LodeSystem 把该格放进再生队列 `{x,y,z,t:12}`；`step()` 递减，到 0 且该格当前是 AIR 时写回 CRYSTAL。
- **只在原位写、只写 AIR**：玩家在晶体位置砌了方块就不长回来（不覆盖玩家地形）。
- 这是 LodeSystem 唯一的写世界格子路径，理由与边界写在代码注释里；
  它写的是"回到基线"，因此存档 diff 会自然消掉这条差异，chem 的 onSet 唤醒只发生一次。
- 不在 tick 里扫描世界：队列长度恒定 ≤ 9（3 矿 × 3 格）。

### 3.4 血量：时间 + 位置
- 100 血；死亡 → 2.2s 复活（`spawnPts` 缓存点 + 被埋顶出）、2.5s 无敌、mana 归 2、素材不变。
- 击杀者 +15 分（唯一入分口 `addScore`）。

### 3.5 手牌：出牌才补给
- 5 格；每次出牌成功（`R.play` 返回 ok）补 1 张；手牌满则新牌进弃牌堆。
- 牌库空 → 弃牌堆洗回（不造牌）；类别手牌（`handClass`）规则不变（同类纯度）。

## 4. 数值账（稳态，用来判断"值不值"）

| 行为 | 60 秒收益 |
|---|---|
| 独占一条矿 | 20 分 + 10 素材 + 9 魔力（0.15×60） |
| 同一分钟里把 3 格晶体采三轮（12s 再生） | +9 素材 +27 魔力（要来回跑，实际 2 轮） |
| 不占矿、只采晶 | 0 分 + 约 9–15 素材（跑图成本高） |
| 一次击杀 | 15 分（≈ 45 秒占矿） |

结论：**占矿是主收入，击杀是快钱，采晶是"在矿上补一口"**。
挡住"只打架不占矿"（45 秒白干一次）与"只占矿不打仗"（对手来抢时你没牌防）。

## 6. 明确不做（写下来防止下一个会话"顺手完善"）

- **不做局外构筑**（方案 B 的卖点）；**不做随机掉落**（会给出牌追溯加噪声）；
  **不加弃牌/换牌按钮**（违反"除移动外一切操作必须出牌"的产品内核；付不起的墙用部分成交解决）。
- **不做死亡掉牌/掉素材**（死亡代价已经是 15 分 + 25 秒离场）。
- **不给占矿加第四条收益**（例如掉卡概率）——成长线的唯一出口是三选一，多了就不可解释。
