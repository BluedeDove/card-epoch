# 终局可达性 R2（kimi · 应第四轮质询，2026-10-17）

> 前提：机制线实测推翻了我 R1（GAMEPLAY_ENDGAME_KIMI.md）的预测——承诺 92%/[330,410]s，实测 44.4%/425.8s。
> 本文先公开纠正错误根源，再给结构性解法。所有新预测在**修正后**的仪器上重放得出（/tmp/endgame_oracle4~6.cjs），
> 且仪器已用机制线的实测校准：同参数重放 = 44.4% / 426s，与实现侧逐位吻合。主干胜分已回 100，本文不把 R1 数字当现状。
> 不改代码、不 commit。

## 0. 公开纠正：我的预言机有个共享累加器 bug

机制线诊断为"结构性自反（胜分 75 提前收束，满速期被截掉）"。这个方向对，但定量主因更丢人：
我的扫描脚本里**热度累加器 heatPts 是六个候选变体共享的**，每个带升温的变体都往同一份热度里又加一遍——
我模拟里的升温速度是真实实现的 4~5 倍，于是 92% 是 bug 的产物。修正（每变体独立累加器）后重放机制线的实现参数，
得到 **44.4% / 426s，与两组独立脚本互证的实测逐位吻合**——仪器现在可信，本文其余数字出自这台校准过的仪器。
另外两处记录：① 我 R1 写"×(1+0.5k)，24 分满速"算错一档（×3 要到 32 分），子代理按公式实现是对的，错在我的括注；
② "代理去打热矿未观测到"同意机制线的定性：RationalAgent 估值表把矿速率写死成 1/3s，看不见矿温——是量具盲，不是机制无效的证据（见 §4 的量具修复）。

## 1. R2 的结构性答案：修"占有判定"，不修"产出曲线"

**占矿宽限（capture grace）**：矿脉归属有 2 秒记忆——占有者离开平台后归属保留 2 秒；
对手站上来立刻转入争抢（宽限当场清零，进攻方不需要等）。就这一条，产出速率、升温、胜分公式全不动。

为什么这是结构性解法而不是又一个参数：

- R1 的自反根源是"复利被收束截断"：任何按产出/分数累计的机制，其兑现期都可能被它自己促成的收束点切掉。
  宽限没有复利——收入对真实占有是**线性**的，越线时刻 = 目标 ÷ 速率，闭式解，不存在截断反馈。
- 它治的是病根：实测占有碎片 99.8% <3 秒、每方等效独占只有 89 秒（18.5%），这不是"玩家没有占矿"，
  而是"玩家在矿边上走位、收割、躲牌，规则把每次抬脚都读成丢矿"。宽限 2 秒后，等效独占 89s → ~369s——
  **4 倍的差距一直是测量口径造的，不是行为**。真人玩家只会比代理更频繁地抬脚（采晶、砌墙都要离开平台），
  所以这不是为 AI 修的夹具，是为真人修的手感：离开两秒去采颗晶不该丢矿。
- 语义干净：离开 ≠ 丢矿；**对手上来 = 立刻丢**（争抢仍即时，防守空窗不白赚）。

## 2. 方案甲（主推）：宽限 2s + 胜分 75，产出曲线不动

### ① 改哪个数

| 项 | 现值 | 改为 |
|---|---|---|
| 归属判定 | 脚踏平台即占，抬脚即丢 | **宽限 2 秒**（LodeSystem 的 owner 加记忆：on 则刷新，无人则倒计时，争抢当场清零） |
| 胜分 | 100（主干现值） | **75** |
| 产出速率 | 1 分/3s/矿 | 不变 |
| 升温（机制线已实现的半套） | 每 8 分 +50%，×3 | **退役**：宽限上线后它不再必要（见预测表），留着只会让收入过早冲线（grace3s+升温实测越线中位 126s，过快） |
| 击杀 +15 | 不变 | 不变（= 胜分 20%，健康线内） |
| 素材被动 +1/6s | 不变 | 不变——宽限让它从"名义存在"变"真的到账"（等效独占 ×4），这正是 R1 对账表设计的 25 素材/分钟的兑现方式 |

### ② 预测（修正仪器，36 局/组，承诺区间；复跑落出区间我公开纠正）

| 组 | score 结局占比 | 越线时刻中位 |
|---|---|---|
| 双理性 | **97%**（承诺 ≥88%） | **329s**（承诺 [300, 360]） |
| mixed | **83%**（承诺 ≥72%） | **371s**（承诺 [340, 400]） |
| mirror（对照组） | **0%** | — |

mirror 恒 0 是**正确行为**不是缺陷：老 AISource 从不占矿（矿分 0.3），击杀场均 ~2（30 分），75 分对它本就不可达——
它是"只打架不占矿"的对照组，贴钟判分就是它应得的结局。这条要写进断言注释，防下一个人把 mirror 的 0% 当回归。
残余的冻结流局限如实声明：宽限会改变 RationalAgent 读到的 owner（它会做不同的走位决策），我的重放看不到这层行为反馈；
97%/329s 是"行为不变"口径下的数字，实现后复跑才是真值——这就是我给出区间而不是点值的原因。

### ③ 副作用

- **抢第二条矿的动机**：不变（两份独立线性收入）。与升温方案不同，宽限不制造"热矿焦点"，争夺动机保持恒定——这是代价也是稳定性。
- **双 PvE 退化角**：和平互蹲对宽限无感（站着不动本来就连续占有），收束时刻 = 75×3 = **225s**，落在上一轮约定的退化窗 [90,240]s 内边缘——比升温方案的 105s 健康一个档。
- **击杀意义**：不变。宽限反而放大击杀收益：死亡造成离场 >2s，宽限耗尽、矿易主。
- **手感红利（真人才有的那条）**：抬脚采晶/躲牌不再丢矿——这条 AI 量不出来，写在这里等用户试玩确认。

### ④ 与定案的冲突清单

- §2.1 "占矿每 3 秒 +1"：补一句归属语义（宽限 2s、争抢即时）；人话段同步。
- 胜分 100→75；升温代码（若已并入主干）退役——**建议删干净，不留半套开关**。
- M7 口径改为"双理性组 score 结局 ≥88%、越线中位 ∈ [300, 360]s；mixed ≥72%"；新增 mirror 组注释（恒贴钟是预期）。
- 加时平分判定：沿用我 R1 提的"独占秒多者胜"（totalHold 已有账本；宽限下 totalHold 读带记忆的 owner 口径，一致）。

## 3. 方案乙（备选）：宽限 3s + 胜分 90

- ① 宽限 2→3s，胜分 90（击杀权重降到 17%），其余同甲。
- ② 预测：双理性 **97% @333s**；mixed **86% @374s**（承诺区间各自 ±10）。归属更粘、节奏更慢、击杀更边缘。
- ③ 副作用：3 秒记忆在观感上更接近"占领进度条"，防守方抬脚容错大到可能被读成"矿赖着不丢"；
  等效占有 duty 到 77%，"争夺"在对局时间里的占比被压缩。适合更偏经营的口味，不适合更偏打架的口味。
- ④ 冲突：同甲，另加击杀权重下降的连锁（若未来要抬击杀回 20%，击杀分需 18，另开一轮对撞）。

## 4. 质询 B：矿温可见性——升温退役后，这题变成"占有可见性"

升温退役后没有矿温要给玩家看；真正需要可见的是**归属与争抢状态**（宽限计时是秒级尾巴，不该做成读秒 UI）：

1. **远读（跨图）**：矿脉光柱按归属着色——无主白、side0/side1 阵营色、争抢中闪烁。实现走 VFX 的 pillar 原子（已有），
   归属变化是稀有事件，零 tick 成本。玩家不过去看也该知道"中矿现在是对手的"。
2. **近读（到场）**：平台水晶发光强度随"本矿本局累计产出"微增（emitOf 读 meta，换档才重建 chunk）——
   不表达温度，表达"这条矿已经被榨了多少"，是纯叙事性的。
3. **HUD**：顶栏三矿归属点（三态：我方/对方/争抢）；准星指到矿平台时 aim 信息行显示"归谁 / 产出中 / 争抢中"（H.TEXT 文案，viewmodel 读 match）。
4. **量具修复（不算玩法改动）**：RationalAgent 估值表把矿速率写死 1/3s——改为读 lodeSys 的实际归属与速率，
   否则任何归属类机制的行为响应都量不到（上一轮"代理不打热矿"的盲区就是这么来的）。

## 5. 需要机制线复跑验证的清单

1. 甲方案全参数：双理性 score 结局 ≥88%、越线中位 ∈ [300, 360]s；mixed ≥72%、中位 ∈ [340, 400]s；T7 中位落 270–420 带。
2. 和平对照组（双 passive 蹲家矿）：score 结局时刻 ∈ [200, 250]s（理论 225s）且必分胜负（加时判独占秒）。
3. mirror 组恒贴钟 = 预期，写进断言注释；但它仍须**分出胜负**（判分/加时链路不许因为 0 矿分而失效）。
4. 素材曲线回归：宽限后占矿被动实际到账 ~8/分钟/矿——确认 M6b（素材流通）仍绿，且工事没有泛滥到堵死走廊（BFS 闸只管生成期不管局内堵塞，这条靠 play_probe 的可达性抽检）。
5. H1 确定性：宽限状态机零 rng，同 seed 逐 tick 一致应自动成立，跑一遍确认。

## 6. 质询 ① 的实测先行回答（/tmp/grace_oracle.cjs，双理性 36 局，103 万 tick-lode 样本）

**你担心的失败模式在当前占有流上不成立**：双方同时在台（contested）只占 **0.03%** 的 tick——
"谁都判定不到独占"的窗口不存在；理性代理是交替占有，从不共台站桩。宽限 2s+清零规则下：
独占 12.0%→38.5%，空台 88%→61.5%，全队产出 2074→6645 分（3.2×）。清零次数/局与素材/分钟等实现侧数字以你的复跑为准。

但顺带量出一条**反面的铁律，比原问题值钱**：我顺手模拟了两个带"连续在场"要求的候选语义——

| 候选语义 | 全队产出 | 死因 |
|---|---|---|
| 宽限 2s + 上台即清零（现行甲方案） | **6645** | — |
| 撼动条：对手须连续在场 1.2s 才破权 + 独占 0.8s 认领 | 3006 | 连续要求与碎片现实冲突：认领条被 <3s 碎片反复打断，矿长期无主 |
| 记忆存活 + 0.5s 延迟暂停 + 独占 1.5s 夺取 | 566 | 同上，更狠 |

**任何"连续在场 N 秒"的要求都会自杀**——与升温轮"只有累计机制活得下来"是同一条定律在占有判定上的投影。
所以万一实现侧真测出 contested 吞产出（行为反馈：突袭者学会戳戳流），修法也必须避开连续要求：

- **候选 1（主推的备胎）：累计撼动条**。对手在台时间**累计**满 1.2s（不要求连续）才破权；撼动条无在场 10s 才衰减。
  戳戳流每次 0.3s 也在攒条——戳四下才撼动，而每次上台都在挨打半径里。手感代价：防守方多一条要看的进度条；
  进攻方"碰一下"彻底无收益，破权变成一个明确的 1.2s 在场承诺。
- **候选 2：余晖产出（归属与产出分层）**。归属照旧即时切换（上台即争抢、UI 诚实），但**产出尾巴归旧主 2s**——
  丢矿后 2 秒内的产出仍打进旧主账上。归属语义零变化、好懂；收入对 poke 免疫。
  手感代价：玩家会看到"矿是对方的，我却还在 +1"，要一行文案解释；且 poke 方压着平台时旧主还在收钱，
  进攻方感受差——所以它排在候选 1 后面。

两个候选都不改"宽限 2s + 胜分 75"的主结构；实现侧复跑若 contested 占比 <5%（我的预测），一个都不用上。
