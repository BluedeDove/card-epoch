## 2. 设计语义记录（复核时请逐条对）

1. **占矿是在场语义，无记忆**：不站就不产；争抢双方零产出。脚底垂直窗口 [台面, 台面+3.5]（容 ±1 整平残差、跳跃 1.25、小柱工事 2 格；高塔凌驾不算占）。
2. **充能记在矿上，暂停不清零**：非独占期充能暂停、进度保留；换主继承残余进度（1v1 下 A→B 直接换主是罕事；语义取"矿的充能"而非"人的存条"，已在类注释写明）。
3. **终局加速**：boost ×2 由 LodeSystem 每 tick 读双方分数自算（≥80 触发），不经过 Scoreboard 中转。
4. **复活占位检查只升不降**：出生柱被垒高 → 顶到新柱面；被挖低 → 保持缓存点（重力接管）。GroundProbe 用 maxRing 0 = 只查原柱，永不横向挪复活点。
5. **lives 夹 0**：是本轮唯一一处"保留字段"的语义微调（原样 `p.lives--` 会出负数进结算面板），其余行为（扣减时机、日志、复活）逐字未动。

## 5. 矿脉与得分实测（/tmp/a1b_lodes.cjs，12 局逐局表在此节末尾的原始输出）

### 5.1 胜负原因分布与 T2 翻红的两半归因
分布：**time 胜 9 局 / open 3 局 / score 胜 0 局 / overtime 胜 0 局**（比分样本 15:0 ~ 75:31）。
- 3 局 open 全是 480s 平分进加时（45:45 / 30:30 / 31:31），**探针窗口 9600 tick 恰等于对局 480s 上限**，加时第一个 tick 都没跑就被测量截断——这是测量窗口伪影；加时机制本身已被 U 级冒烟钉死（§3）。镜像 AI 局 25% 打到平分也是真实信号（同水平对局分差小）。
- T2 从绿转红我没有动任何阈值；是否给加时局放行更长的测量窗口，属 play_probe 所有者（A1-a 线）与机制线的口径决定。

### 5.2 T7 贴顶（480/480）的如实话
任务书预期"中位从 184s 向 270–420 靠拢"——**没有发生**：12 局全部打满 480s 时间帽。原因：分数节奏被设计成"占矿 3s+1 + 击杀 15"，而探针里**矿脉产出 ≈ 0**（下条），100 分全靠 7 次击杀，镜像 AI 八分钟只产出 2–9 次玩家击杀 → 全员顶到时间帽。分数钟接管后局时长由"有没有人得分"决定；AI 不占矿，时长就贴顶。这不是时长口径的失败，是"AI 无占矿行为"的同一根因在 T2/T7 上的两面投影。

### 5.3 公平指标（任务书点名的额外数）：**占矿多=胜者 2 局 / 占矿多却输 5 局 / 持平 2 局 / 未分 3 局**
失衡成立但根因要分清：**每条矿的独占时长全部只有 0–7 秒**（噪声级路过，AI 从不为占矿停留），矿产出分全场 ≈0–2。
所以"占矿多却输"里的"占矿多"是 1–7 秒的路过噪声，比分实际上纯由击杀构成（15 分/杀 vs 占矿 ≈0 分）。
**"击杀 15 vs 占矿 1 分/3s"这个比值本身是否失衡，要在"有人真占矿"的局里才测得到**——AISource 没有占矿动机
（它只追人打；定案 §7.1 条 17 的 RationalAgent 才是教它占矿的那一步）。建议：此指标挂到 RationalAgent 落地后再判。
